# sumsbkz-py

Code and data for the paper *New records for equal sums of like powers via lattice sieving*
by J. G. Childers.

An identity of type (k,m,n) is a₁ᵏ+…+aₘᵏ = b₁ᵏ+…+bₙᵏ in positive integers with m ≤ n.
J.-C. Meyrignac's tables (<http://euler.free.fr>) record the least known n for each k and m.
This repository contains

- a Python port of **SumsBKZ** (2000–2003), the lattice-reduction search that produced many of
  the records, and the rebuilt original C++ sources;
- the search used for the paper: the relation lattice of 1ᵏ,…,Nᵏ is sieved with the General
  Sieve Kernel (G6K, or G6K-GPU), and the whole sieve database serves as the move set of a greedy
  descent on the numbers of terms;
- the methods of the paper for 33 ≤ k ≤ 100: coset starts for forced moments, completions of
  congruence solutions, structured congruence solutions, and descent from known identities;
- the scripts that produce every table and number in the paper, the paper source, and the
  data archive with a standalone verifier.

## Verifying the results

The directory `archive/` certifies every improved table entry and needs only Python 3:

```bash
cd archive && python3 verify.py
```

It checks each identity in exact integer arithmetic and compares it with the reference value of
the table entry; see `archive/README.md`.

## Layout

| Path | Contents |
|---|---|
| `sievesearch.py` | sieve and descent search (CPU or GPU) |
| `sumsbkz.py` | Python port of SumsBKZ 1.3.3 (BKZ and Yura's post-processing step) |
| `eslp/` | relation lattice, sieving, descent (CPU and CUDA), combination, identity parsing |
| `tools/` | completions (`complete.py`, `structsolve.py`), coset starts (`momentstart.py`), descent from known identities (`recordstart.py`), experiments, and the table and archive generators |
| `paper/` | LaTeX source; `paper/tables/` and `paper/data/` are generated |
| `archive/` | data archive: identities, reference values, verifier, checksums |
| `results/` | the identities and logs of all runs counted in the paper |
| `data/archive/` | the record databases of 2001–2003 (`database.txt`, `datahigh.txt`, `dataprime.txt`) |
| `remote/`, `nrp/` | job scripts for the Turing cluster (CSUF) and the National Research Platform |
| `legacy/` | original SumsBKZ, sumsbkzmod and decompose sources (`legacy/original/`) and a version of `sumsbkz.cpp` that builds with NTL 11 |
| `patches/` | portability fixes for G6K on ARM, against the commit in `g6k-base-commit.txt` |

## Requirements

- Python 3.12, fplll 5.5.0, fpylll 0.6.4, NumPy, numba (`requirements.txt`);
- G6K at commit `c71e084` (`patches/g6k-base-commit.txt`) for CPU sieving;
- for GPU sieving, G6K-GPU-Tensor (branch `python3lwe`, commit `e0e17ad`), CUDA 12.8–12.9 and
  numba-cuda.

On macOS:

```bash
brew install uv fplll ntl
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.txt
```

The fpylll wheel's built-in path to fplll's BKZ strategies does not exist on macOS;
`eslp/lattice.py` falls back to Homebrew's `share/fplll/strategies/default.json` (override
with `FPLLL_STRATEGIES`).

## Usage

```bash
# sieve and descent with bases 1..60 for k = 20..30
.venv/bin/python sievesearch.py -k 20 30 -N 60 --radius 1.5

# the 2003 procedure (SumsBKZ defaults: bases 1..40 to 1..50, BKZ-20)
.venv/bin/python sumsbkz.py -n 40 50 -k 9 32 -b 20 --passes 10
```

The searches compare their output with Meyrignac's current table. Fetch his pages and database
into `data/euler_free_fr/raw/` and run `python3 tools/scrape_euler.py` to build
`data/euler_free_fr/`. The tables of the paper are then regenerated by

```bash
.venv/bin/python tools/make_tables.py && .venv/bin/python tools/congruence.py
.venv/bin/python tools/controls.py && .venv/bin/python tools/logstats.py
.venv/bin/python tools/make_archive.py
```

The legacy program builds with

```bash
c++ -O2 -std=c++11 -I/opt/homebrew/include -o legacy/sumsbkz legacy/sumsbkz.cpp -L/opt/homebrew/lib -lntl -lgmp
```

## Not included

Meyrignac's current pages and database, the programs NewLC, ResultLC and ysum, and J. Wróblewski's congruence solutions are the work of others and
are not distributed here. The identities obtained from them are in `archive/` and `results/`.
The archive records SHA-256 checksums of the snapshot of Meyrignac's site that was used.
